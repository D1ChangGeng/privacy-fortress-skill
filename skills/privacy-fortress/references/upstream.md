# 上游网络可见性与规则变更审查

## 1. 按观察者描述，不写“加密后无人可见”

| 层/信号 | 本地网络、校园网或 ISP 通常仍可能看到 | 本方案能做什么 | 必须保留的边界 |
|---|---|---|---|
| 接入归因 | 账号、MAC、内网 IP、接入位置、在线时长 | 仅保留必要认证与私网直连 | 这是接入归因，不因代理消失 |
| 五元组与目的 IP | 到代理入口/中转的连接、时长、字节量、连接数 | 将敏感目的收敛到受控入口 | 入口及加密流量模式仍可见 |
| 传输与时序 | 长连接、突发、TCP/UDP、QUIC、重连与活动时段 | 不受控 UDP 可拒绝，敏感连接送链 | 不能证明流量分析失效 |
| DNS | 明文 UDP/53 查询、透明代答和投毒 | 敏感域 DoH-over-proxy、TUN 劫持、最小 split-DNS | 国内/内网明文例外仍暴露查询兴趣 |
| TLS/HTTP | 直连连接的 SNI、ALPN、指纹；隧道连接特征 | 敏感 TLS 封装在隧道内 | 隧道协议本身可能被识别 |
| DIRECT 例外 | 例外域名/IP、真实公网来源与内容元数据 | 例外最小化、记录所有者和用途 | 目标服务与本地网络都可见该直连 |
| 主动探测 | 对公网入口的 banner、开放端口和响应 | 不在入口暴露无关服务，定期复核 | 不等于入口不可被发现 |

链式代理只重新分配信任：入口通常知道真实来源，最终出口知道目标连接，目标服务看到最终出口。不得写“链式后任何一方都看不到真实 IP”。

## 2. 新增或修改规则时必问

| 变更 | 必须重验 |
|---|---|
| 新增 UDP 放行 | STUN/WebRTC、QUIC、IPv6、代理停止状态 |
| 新增 DIRECT 进程/域名/IP | 目标是否可关联境外账号，helper/内嵌 SDK 是否继承直连 |
| 新增 GeoSite/GeoIP 大类 | 误判方向、最终 MATCH 顺序、境外共享域名是否被截走 |
| 修改 DNS/fallback/bootstrap | 实际递归解析器、DoH 是否仍经代理、节点恢复是否形成回环 |
| 切换节点/中转/住宅出口 | 公网 IP、ASN、DNS、WebRTC、账号使用窗口 |
| 切换 VPN/网关客户端 | 配置事实源、端口、TUN 所有者、锁死/防火墙、双实例 |
| 新增检测哨兵 | 检测请求自身走哪条网络路径，失败是否只记 WARN |

## 3. 最小证据

保存日期、网络环境、测试应用、预期路径和观察结果；不要保存 Cookie、账号页或完整凭据。检测站超时/403/空结果记 UNKNOWN 或 WARN，不记“无泄漏”。
