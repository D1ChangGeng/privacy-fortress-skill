# 方法论：威胁模型、信号台账与证据

## 1. 先确定观察者

分别列出本地网络运营者、代理/VPN 提供商、目标网站、已登录服务、同机应用和物理接触者能看到什么。一个控制对某个观察者有效，不代表对所有观察者有效。

常见目标：

- 不让目标网站直接看到本地公网 IP；
- 不让本地网络看到明文境外 DNS 查询；
- 代理异常时关键应用不直连；
- 减少浏览器、账号、文件和 Agent 上下文中的不必要关联；
- 保持配置可审计，升级或换网络后能发现漂移。

## 2. 五类信号

| 类别 | 例子 | 主要控制 |
|---|---|---|
| 网络观测 | 公网 IP、ASN、IPv6、DNS、WebRTC、路由和时延 | VPN/网关、加密 DNS、防火墙、浏览器策略 |
| 系统声明 | 时区、区域、语言、设备与系统版本 | 保持合理一致、最小权限；不默认伪造 |
| 应用与账号 | 登录态、支付、通讯录、权限、广告 ID | 数据最小化、权限收缩、独立 profile |
| 内容与元数据 | Git 邮箱、文件作者、EXIF、聊天和截图 | 发布前审查与剥离，不上传秘密 |
| 行为与指纹 | 使用时间、访问模式、TLS、Canvas、硬件 | 接受部分残余，避免夸大网络层作用 |

## 3. 镜像三问

对每个信号依次问：

1. **能否减少采集？** 例如撤销定位、通讯录、后台刷新权限。
2. **能否减少外发？** 例如统一出口、关闭非必要遥测、限制应用网络。
3. **能否验证结果？** 例如双状态测试、解析器名单、权限回读。

不能以“修改了表面值”替代减少采集和外发。也不能以“本地不可读”推断“服务商不知道”。

## 4. 证据等级

| 标记 | 含义 | 可以怎样表述 |
|---|---|---|
| TESTED | 在当前设备、当前网络实际观察 | “本次实测为……” |
| CONFIG | 仅从配置推断 | “按配置应当……，尚待实测” |
| UNKNOWN | 未测、不可达或平台不可见 | “未知/需要人工复核” |
| RESIDUAL | 已知无法由本方案消除 | “保留该暴露面，原因是……” |

报告必须带日期和网络环境。换设备、换网络、重启或升级后，旧 TESTED 只能作为历史证据。

## 5. 信号台账模板

| 信号 | 当前证据 | 目标 | 控制与所有者 | 验证方式 | 状态 | 残余/回退 |
|---|---|---|---|---|---|---|
| 公网 IPv4 | 待采集 | 目标服务只见受控出口 | 唯一 VPN/网关 | 两个独立端点+目标应用 | UNKNOWN | 代理停止时断网；Rollback R1 |
| DNS | 待采集 | 不见非预期本地解析器 | 网关 DNS 模块 | 深度 DNS 测试 | UNKNOWN | 加密上游故障时断网或告警 |
| WebRTC | 待采集 | 不出现本地/真实公网候选 | 浏览器策略+网络层 | 浏览器实测 | UNKNOWN | 扩展和原生应用另行审计 |

## 6. 最小权限与最小数据

- 只收集解决当前问题所需字段；优先保留状态，不保留标识值。
- 配置中的用户名、密码、UUID、订阅 URL、私钥和 token 不进入报告或 Git。
- 在线检测前说明会联系哪些第三方；公共检测站也会看到当前出口。
- 远程导入配置时优先本地限时通道，完成后关闭；不上传订阅转换站或公开网盘。
