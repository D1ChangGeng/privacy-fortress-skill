# 浏览器与 Web 信号

## 1. 基础收口

- 只保留一个明确的 DNS 架构：浏览器 Secure DNS 与系统/网关 DNS 不应形成未审计的双通道。
- Chromium 可评估 `WebRtcIPHandling=disable_non_proxied_udp`；Firefox/Safari 使用各自受支持设置。策略值必须重启后回读并实测。
- 阻止不必要的定位、通知、摄像头、麦克风、剪贴板和自动下载权限。
- 每个不相干身份使用独立 profile；无痕窗口不等于独立身份。
- 不为“反指纹”安装来源不明扩展；扩展本身拥有高价值读取权限。

## 2. 语言、时区与指纹

保持语言、时区、账号资料与实际使用合理即可。不要默认把系统改成另一个国家，也不要承诺这些值与 IP 一致就能匿名。原生应用可能读取与浏览器不同的区域字段，自动化检测站只覆盖网页可观察面。

Canvas、WebGL、字体、TLS、硬件与行为指纹通常是概率性标识。目标应是减少跨身份关联和不必要泄露，而不是追求每次结果随机或“指纹为零”。过度伪造反而增加不一致和可用性问题。

## 3. 浏览器分工

如果使用代理/直连双浏览器：

- 代理浏览器只处理需要受控出口的站点，必要时加 killswitch；
- 直连浏览器是有意识的真实出口面，不登录希望隔离的账号；
- 新浏览器默认未覆盖，先审计再使用；
- 不用书签同步、共享扩展账号或剪贴板把两个身份重新关联。

## 4. 验证

用普通浏览窗口而非只跑自动化实例，检查：公网 IP、DNS 深度测试、WebRTC 候选、IPv6、语言和时区。自动化结果可能因 webdriver、无头模式、扩展或独立 profile 而不同。

检测站结论只代表当时页面可见项；Cloudflare/AI 服务是否可用属于服务风控，不是隐私分数，也不应尝试绕过验证。
