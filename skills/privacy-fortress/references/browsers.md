# 浏览器、Web 信号与远程受控浏览

## 1. 基础收口

- 浏览器 Secure DNS 与系统/网关 DNS 采用一个经过审计的架构。
- Chromium 可评估 `WebRtcIPHandling=disable_non_proxied_udp`；Firefox/Safari 使用各自受支持设置。重启回读并用普通窗口实测。
- 定位、通知、摄像头、麦克风、剪贴板和自动下载按最小权限配置。
- 每个不相干身份使用独立 profile，Cookie、存储、扩展和同步账号分别审查。
- 扩展只保留可信且必要的项目，扩展本身具有高价值读取权限。

## 2. 浏览器分工

代理浏览器处理受控出口站点，直连浏览器承担明确的 domestic 业务：

- 代理浏览器可加 killswitch，局域网放行按认证需求决定；
- 直连浏览器是有意的真实出口面，账号与书签同步按隔离目标管理；
- 新浏览器先标 UNKNOWN，确定角色并验收后使用；
- 直连进程规则与最终 MATCH 的顺序需要实测，误点境外站时行为符合设计；
- 剪贴板、共享扩展账号和文件下载也可能重新关联两个场景。

## 3. 语言、时区与指纹

语言、时区、账号资料和长期使用场景保持合理一致。Canvas、WebGL、字体、TLS、硬件与行为指纹用于概率性识别，目标是减少跨身份关联和不必要暴露。检测结果按具体字段解释，避免用单一“指纹分数”替代分析。

## 4. 移动设备远程控制桌面浏览器

需要减少移动浏览器设备型号、UA-CH、WebGL 或系统语言暴露时，可让手机只承担远程显示和输入，网页在受控桌面浏览器的独立 profile 中执行：

1. 桌面使用独立、未同步的 profile，只开放目标站点；
2. 手机端不导入日常 Cookie、账号文件或敏感剪贴板；
3. 审计桌面出口、DNS、WebRTC、语言、时区和实际请求头；
4. 日常关闭远程控制通道，使用后停止临时服务并回读端口；
5. 远控供应商、账号、桌面硬件/TLS 指纹和远控权限单独记入台账。

这种方式改变网页执行位置，账号、内容和远控信任仍按各自证据评估。

## 5. 验证

普通浏览窗口检查公网 IP、DNS 深度测试、WebRTC 候选、IPv6、语言和时区。自动化实例用于补充请求头或脚本证据，结果受 webdriver、无头模式、扩展和 profile 影响。服务风控与隐私配置分别记录，检测站结论只代表当时页面可见项。
